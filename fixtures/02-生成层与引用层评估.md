# RAG评估知识系统-02-生成层与引用层评估

## 1. 生成层和引用层的位置

在 RAG 链路中，生成层和引用层位于后半段：

```text
retrieved evidence
→ prompt
→ LLM
→ answer
→ citation
```

这一层直接决定用户看到的结果。

检索和证据层负责提供材料。

生成层负责把材料组织成答案。

引用层负责把答案和来源绑定起来。

因此，生成层与引用层评估关注：

```text
答案是否回应问题；
答案是否基于证据；
答案是否正确、完整、清楚；
答案是否符合任务要求；
引用是否存在；
引用是否真实支撑结论；
引用是否可追溯。
```

如果没有这一层评估，系统只能知道“找到了什么”，但不能知道“回答得怎么样”。

---

## 2. 生成层评估对象

生成层覆盖：

```text
prompt
context
llm client
generation config
answer
refusal
output format
```

常见变量包括：

```text
prompt 模板；
证据呈现方式；
是否要求引用；
是否要求拒答；
答案长度；
输出结构；
模型；
温度；
上下文长度；
max_tokens；
是否允许常识补充。
```

生成层的核心问题是：

```text
模型是否在给定证据和任务要求下，生成了合格答案。
```

它不是单纯评模型能力。

因为生成结果同时受到：

```text
证据质量；
prompt 约束；
模型能力；
输出格式；
上下文长度；
生成参数。
```

影响。

---

## 3. 生成层的三条关系

生成层评估至少要看三条关系。

```text
answer ↔ question
answer ↔ evidence
answer ↔ reference / rubric（评分标准）
```

### 3.1 answer ↔ question

这条关系看答案是否回应问题。

关注：

```text
是否答题；
是否偏题；
是否遗漏问题中的关键要求；
是否回答了错误对象；
是否把对比题答成单点解释；
是否把流程题答成概念说明。
```

常见指标：

```text
answer_relevancy
task_completion
question_coverage
```

### 3.2 answer ↔ evidence

这条关系看答案是否基于证据。

关注：

```text
答案中的结论是否能从 context 推出；
是否加入无证据事实；
是否靠模型自身知识补全；
是否夸大证据；
是否把证据中的限制条件删掉。
```

常见指标：

```text
faithfulness
unsupported_claim_count
hallucination_rate
evidence_grounding
```

### 3.3 answer ↔ reference / rubric

这条关系看答案是否满足参考标准。

关注：

```text
答案是否正确；
是否完整；
是否覆盖关键点；
结构是否符合任务类型；
解释是否清楚；
是否符合预期行为。
```

常见指标：

```text
answer_correctness
completeness
rubric_score
expected_behavior_match
```

这一条通常最依赖人工标准或高质量 rubric。

如果没有可靠参考答案，就需要通过 expected_behavior、expected_evidence、人工抽查或 LLM judge 辅助判断。

## 4. 生成层常见指标

生成层指标可以分为五类。

### 4.1 相关性指标

```text
answer_relevancy
question_coverage
topic_match
```

它们回答：

```text
答案有没有围绕问题回答？
```

### 4.2 忠实度指标

```text
faithfulness
unsupported_claim_count
hallucination_rate
```

它们回答：

```text
答案是否被证据支撑？
```

### 4.3 正确性与完整性指标

```text
answer_correctness
completeness
key_point_coverage
rubric_score
```

它们回答：

```text
答案是否正确、完整、达到任务要求？
```

### 4.4 拒答指标

```text
refusal_correctness
over_refusal
under_refusal
```

它们回答：

```text
该答时是否回答；
不该答时是否拒答；
证据不足时是否说明原因。
```

### 4.5 格式指标

```text
format_validity
json_validity
citation_format_validity
section_structure_validity
```

它们回答：

```text
答案是否符合系统要求的输出格式？
```

生成层指标不能只看一个。

例如：

```text
答案可能切题，但不忠实；
答案可能忠实，但不完整；
答案可能正确，但没有引用；
答案可能格式合格，但内容很弱；
答案可能拒答安全，但误拒了可回答问题。
```

## 5. 生成层常见失败

生成层常见失败包括：

```text
generation_error
hallucination
unsupported_claim
answer_incomplete
answer_irrelevant
format_error
over_refusal
under_refusal
verbosity_error
```

含义分别是：

```text
generation_error：证据足够但模型生成错误；
hallucination：模型生成无证据内容；
unsupported_claim：答案中的部分结论没有证据支撑；
answer_incomplete：答案遗漏关键点；
answer_irrelevant：答案没有回应问题；
format_error：输出格式不符合要求；
over_refusal：证据足够却拒答；
under_refusal：证据不足却强答；
verbosity_error：过长、过短或结构失衡。
```

修复方向通常包括：

```text
调整 prompt；
明确拒答规则；
减少无关 context；
增加证据结构化；
更换模型；
调整温度；
限制答案长度；
加入格式校验；
加入生成后检查。
```

---

## 6. Prompt 在生成评估中的位置

Prompt 是生成层的重要控制面。

它决定模型如何使用证据。

一个 RAG prompt 通常要明确：

```text
只基于给定证据回答；
证据不足时拒答；
不要编造来源；
引用格式；
答案结构；
答案长度；
是否允许常识补充；
如何处理多来源证据。
```

Prompt 评估关注：

```text
约束是否清楚；
证据是否容易被模型读取；
引用要求是否明确；
拒答规则是否明确；
不同问题类型下是否稳定；
是否诱发模板化或过度拒答。
```

Prompt 改动适合做回归评估。

因为 prompt 很容易带来副作用。

例如：

```text
更严格的拒答规则可能减少幻觉，但增加误拒；
更长的答案要求可能提升完整性，但增加延迟；
更复杂的引用规则可能提升可追溯性，但降低格式稳定性。
```

## 7. 引用层评估对象

引用层覆盖：

```text
citation
source_id
doc_id
chunk_id
metadata
offset
citation binding
citation support
```

引用层的核心问题是：

```text
答案里的结论，能否追溯到真实来源，并被对应来源支撑。
```

引用不是装饰。

引用要完成三件事：

```text
说明答案来自哪里；
让用户可以回查证据；
约束模型不要无证据扩写。
```

引用层评估关注：

```text
有没有引用；
引用数量是否满足要求；
引用格式是否正确；
引用是否能回到原始资料；
关键结论是否都有引用；
引用内容是否支撑结论；
是否存在无关引用；
是否存在引用和答案错位。
```

---

## 8. 引用层的双向检查

引用评估可以分成两个方向。

```text
answer claim → citation
citation → answer claim
```

### 8.1 answer claim → citation

这条线看：

```text
答案里的关键结论有没有被引用支撑。
```

它回答：

```text
该引的有没有引？
```

例如：

```text
答案中出现一个事实判断；
需要检查它是否绑定了对应证据。
```

### 8.2 citation → answer claim

这条线看：

```text
给出的引用是否真的和答案相关。
```

它回答：

```text
引的东西有没有用？
```

例如：

```text
答案给了两个引用；
但其中一个只是来自同一文档，并没有支撑对应结论。
```

这两个方向都重要。

只看有没有引用，容易把装饰性引用当成有效引用。

只看引用是否相关，又可能漏掉答案中没有被引用支撑的结论。

---

## 9. 引用层常见指标

引用层指标可以分为四类。

### 9.1 存在性指标

```text
has_citation
citation_count
citation_format_validity
```

它们回答：

```text
答案有没有引用，引用格式是否存在。
```

### 9.2 覆盖性指标

```text
citation_coverage
claim_citation_coverage
key_claim_coverage
```

它们回答：

```text
答案中的关键结论是否都有引用。
```

### 9.3 支撑性指标

```text
citation_support_label
citation_support_score
citation_not_supporting_claim
```

它们回答：

```text
引用是否支撑对应结论。
```

### 9.4 可追溯指标

```text
citation_source_ids
citation_doc_ids
citation_chunk_ids
metadata_complete
offset_available
```

它们回答：

```text
引用能不能回到原始文档和具体片段。
```

## 10. 引用层常见失败

引用层常见失败包括：

```text
missing_citation
citation_format_error
citation_source_error
citation_not_supporting_claim
citation_overclaim
citation_undercoverage
citation_fallback_only
```

含义分别是：

```text
missing_citation：答案没有引用；
citation_format_error：引用格式错误；
citation_source_error：引用来源不存在或无法追溯；
citation_not_supporting_claim：引用不支撑对应结论；
citation_overclaim：答案结论超出引用证据；
citation_undercoverage：部分关键结论没有引用；
citation_fallback_only：引用只是兜底附带，并未真实绑定答案。
```

修复方向通常包括：

```text
改进 citation binding；
让生成阶段按 claim 绑定引用；
增加引用格式校验；
增加 citation support judge；
保留 source_id / doc_id / chunk_id；
在 prompt 中明确引用规则；
避免模型自己编造引用。
```

## 11. 生成层与引用层的关系

生成层和引用层密切相关，但不能混为一谈。

可能出现几种情况：

### 11.1 答案好，引用也好

理想情况。

```text
答案切题、忠实、完整；
引用覆盖关键结论；
引用可以回到真实证据。
```

### 11.2 答案好，引用不好

这种情况很常见。

```text
答案内容基本正确；
但引用缺失、格式错误或支撑不足。
```

此时问题主要在 citation binding。

### 11.3 答案不好，引用存在

引用存在不代表答案可靠。

可能是：

```text
模型给了引用；
但答案超出了证据；
引用只是装饰；
关键结论没有被支撑。
```

### 11.4 答案拒答，引用不适用或需说明

知识不足时，系统可能拒答。

此时引用评估要看：

```text
是否说明证据不足；
是否引用已有但不足的材料；
是否避免强行给出无支撑结论。
```

---

## 12. 小结

生成层评估回答：

```text
模型是否基于证据生成了合格答案。
```

引用层评估回答：

```text
答案是否能被真实来源支撑和追溯。
```

生成层至少看三条关系：

```text
answer ↔ question
answer ↔ evidence
answer ↔ reference / rubric
```

引用层至少看两个方向：

```text
answer claim → citation
citation → answer claim
```

一句话收束：

```text
生成层与引用层评估的价值，是把“答案看起来不错”进一步拆成“是否切题、是否忠实、是否完整、是否有真实可追溯的证据支撑”。
```

第三批建议写 `06-实验变量与回归集设计`、`07-指标体系与报告输出`、`08-评估工具与RAGAS指标拆解`。
